How it works

A VM is a cache. The bucket is the truth.

The same design as HanuDB, the database it runs on: one free-tier machine does the work, and everything durable lives in object storage that costs cents.

Collect

The 8 KB script sends batched events with a beacon. The server checks the project's allowed domains, adds geo and device, and buffers.

Store

Events become zstd Parquet files, one per project per day; recordings become gzip chunks. HanuDB keeps users, projects, sessions and persons.

Query

Apache DataFusion scans the local mirror of those files. Dashboards are SQL templates, so the explorer gives you the same table.

Cost

About one cent a month. Really.

There is no database server to pay for and queries never read the bucket. The only metered thing is object writes, and events are batched into a few hundred of them a day.
